# Enterprise AI Customer Complaint Resolution Platform

## Application Generation Prompt

You are a senior full-stack engineer and enterprise AI architect.

Build a complete, runnable, production-oriented academic prototype
called:

**Enterprise AI Customer Complaint Resolution & Support Agent**

The application demonstrates how Agentic AI can be deployed in an
enterprise environment to analyze customer complaints, retrieve company
policies, inspect order information, determine an appropriate
resolution, execute permitted actions through tools, request human
approval for sensitive actions, and maintain audit/monitoring
information.

The project must be functional, easy to run locally, cleanly structured,
and suitable for an academic capstone demonstration.

------------------------------------------------------------------------

# 1. PRIMARY OBJECTIVE

Build a web application where a customer can:

1.  Log in.
2.  Submit a complaint or support request.
3.  Enter an order ID when applicable.
4.  Have an AI agent analyze the complaint.
5.  Classify the complaint.
6.  Retrieve relevant company policies using RAG.
7.  Retrieve order/customer information using tools.
8.  Determine whether the complaint can be automatically resolved.
9.  Execute permitted actions such as:
    -   refund request
    -   replacement request
    -   support ticket creation
    -   order-status response
10. Escalate sensitive or uncertain cases to a human support agent.
11. Track the complaint status.
12. View the final resolution and explanation.

The application must also provide an **enterprise monitoring dashboard**
for administrators/support managers.

------------------------------------------------------------------------

# 2. IMPORTANT IMPLEMENTATION PRINCIPLE

Do not build this as a simple chatbot.

It must clearly demonstrate **Agentic AI** through:

-   multiple specialized agents
-   agent orchestration
-   tool/function calling
-   retrieval-augmented generation
-   state transitions
-   conditional decisions
-   human-in-the-loop approval
-   failure handling
-   audit logging
-   monitoring

The application should demonstrate the flow:

**User -\> Supervisor Agent -\> Specialized Agents -\> Tools/RAG -\>
Decision -\> Approval or Automatic Action -\> Resolution -\> Audit**

Responsibilities:

-   create workflow state
-   determine which agents are required
-   invoke specialized agents
-   evaluate results
-   determine next step

-   handle failures
-   produce final resolution


Example policy:

``` text
Replacement Policy

A customer may request replacement within 7 days of delivery

Proof of damage may be required.

Orders above the configured high-value threshold require

```

The Policy Agent should:

1.  receive the complaint context
2.  generate a retrieval query
3.  search ChromaDB
4.  retrieve relevant policy chunks
5.  return policy evidence
6.  provide citations/references to the policy document names

Never allow the LLM to invent company policy when relevant policy
documents are available.

# 11. RESOLUTION AGENT

The Resolution Agent combines:

-   complaint information

-   order information
-   policy evidence

Possible resolutions:

``` text
AUTO_REFUND
AUTO_REPLACEMENT
ORDER_STATUS_RESPONSE
CREATE_SUPPORT_TICKET
HUMAN_REVIEW
REJECT_REQUEST
REQUEST_MORE_INFORMATION
```

Example:

``` json

  "resolution": "AUTO_REPLACEMENT",
  "reason": "Product was reported damaged within the 7-day replacement period.",
  "requires_approval": false,
  "confidence": 0.91
}
```

Do not use confidence scores as fake factual probabilities. If the LLM
produces a confidence value, clearly treat it as an internal model
estimate.

# 13. HUMAN-IN-THE-LOOP

Sensitive operations must not be automatically executed.

For example:

``` text
Refund amount > ₹5,000
        ↓
Human approval required
```

Also require approval for:

-   high-value refunds
-   unusual requests
-   policy conflicts
-   low-confidence/uncertain cases
-   repeated failed tool calls
-   requests involving suspicious activity

Workflow:

``` text
AI Recommendation
       ↓
Approval Required
       ↓
Support Agent
   ┌────┴────┐
 Approve   Reject
   │          │
   ▼          ▼
Execute    Escalate/Close
```

The approval decision must be stored in the audit log.

# 17. AI SECURITY / GUARDRAILS

Implement basic protections against:

## Prompt injection

Detect suspicious instructions such as attempts to:

-   reveal system prompts
-   ignore safety rules
-   expose secrets
-   bypass approval
-   execute unauthorized tools

Authorization must be enforced by backend code.

## Tool restrictions

The LLM should never be able to directly execute arbitrary code.

## Data boundaries

through an LLM query.
